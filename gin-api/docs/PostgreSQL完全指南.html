📖 什么是 PostgreSQL？

PostgreSQL 是一个功能强大的开源对象关系型数据库系统，起源于加州大学伯克利分校的 POSTGRES 项目。它拥有超过 35 年的活跃开发历史，以其可靠性、功能丰富性和性能著称。

🎯 一句话理解

PostgreSQL = 关系型数据库 + 对象特性 + NoSQL 能力 + 企业级功能

谁在使用 PostgreSQL？

Apple 使用 PostgreSQL 支撑 App Store 和其他服务
Instagram 存储数十亿张照片的元数据
Netflix 推荐系统和用户数据
Spotify 音乐库和播放列表
NASA 科学数据存储和分析

💡 JSON vs JSONB 的区别

-- JSON：存储原始文本，保留格式
data JSON = '{"name": "Alice", "age": 25}'

-- JSONB：二进制存储，可建索引，性能更好
data JSONB = '{"age": 25, "name": "Alice"}'  -- 重新排序

-- JSONB 上可以建索引！
CREATE INDEX idx_data ON users USING GIN (data);
SELECT * FROM users WHERE data @> '{"name": "Alice"}';

SQL 语法差异

1. 自增ID - MySQL vs PostgreSQL

-- MySQL
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    ...
);

-- PostgreSQL
CREATE TABLE users (
    id SERIAL PRIMARY KEY,  -- 或 BIGSERIAL
    ...
);

-- 或使用 GORM（通用）
type User struct {
    ID uint `gorm:"primaryKey"`
    ...
}

2. 插入并返回 - MySQL vs PostgreSQL

-- MySQL（需要两步）
INSERT INTO users (name) VALUES ('Alice');
SELECT LAST_INSERT_ID();

-- PostgreSQL（一行搞定）⭐
INSERT INTO users (name) VALUES ('Alice') RETURNING id;

3. 分页查询 - MySQL vs PostgreSQL

-- MySQL（传统方式）
SELECT * FROM users LIMIT 10 OFFSET 20;

-- PostgreSQL（支持更多语法）⭐
SELECT * FROM users LIMIT 10 OFFSET 20;
-- 或使用 OFFSET...FETCH
SELECT * FROM users OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;
-- 或使用 CTE（更优雅）
WITH limited AS (
    SELECT * FROM users ORDER BY id DESC
)
SELECT * FROM limited OFFSET 20 LIMIT 10;

4. Upsert（插入或更新）- MySQL vs PostgreSQL

-- MySQL（使用 ON DUPLICATE KEY UPDATE）
INSERT INTO users (id, name) VALUES (1, 'Alice')
ON DUPLICATE KEY UPDATE name = 'Alice';

-- PostgreSQL（使用 ON CONFLICT）⭐
INSERT INTO users (id, name) VALUES (1, 'Alice')
ON CONFLICT (id) DO UPDATE SET name = 'Alice';

-- 或更简洁
INSERT INTO users (id, name) VALUES (1, 'Alice')
ON CONFLICT (id) DO UPDATE SET name = EXCLUDED.name;

5. 软删除 - MySQL vs PostgreSQL

-- MySQL（手动管理）
ALTER TABLE users ADD COLUMN deleted_at DATETIME;
SELECT * FROM users WHERE deleted_at IS NULL;

-- PostgreSQL（GORM 原生支持）
type User struct {
    DeletedAt gorm.DeletedAt `gorm:"index"`
}
// GORM 自动处理软删除，查询时自动加上 WHERE deleted_at IS NULL

6. 条件更新 - MySQL vs PostgreSQL

-- MySQL
UPDATE users SET status = 1 WHERE id = 1;

-- PostgreSQL（支持 RETURNING）⭐
UPDATE users SET status = 1 WHERE id = 1 RETURNING *;

7. 数组类型 - PostgreSQL 独有

-- PostgreSQL 支持数组字段
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100),
    tags TEXT[]  -- 数组类型
);

INSERT INTO products (name, tags) VALUES ('iPhone', ARRAY['手机', '苹果', '高端']);

-- 查询数组包含某值
SELECT * FROM products WHERE '苹果' = ANY(tags);

-- MySQL 没有原生数组支持，需要用 JSON 或单独建表

8. 正则表达式 - PostgreSQL 更强大

-- PostgreSQL（完整正则支持）⭐
SELECT * FROM users WHERE email ~* '^[a-z]+@example\.com$';

-- ~  区分大小写匹配
-- ~* 不区分大小写匹配
-- !~ 不匹配

🎯 什么时候选 PostgreSQL？

  • ✅ 需要处理 JSON/NOSQL 数据
  • ✅ 需要复杂查询和存储过程
  • ✅ 需要数组、范围等特殊数据类型
  • ✅ 大数据量分页查询
  • ✅ 需要高并发写入
  • ✅ 对数据完整性要求极高
  • ✅ 需要高级索引（GIN、GiST）

⚠️ 什么时候选 MySQL？

  • ✅ 传统 Web 应用，开发快速
  • ✅ 团队对 MySQL 经验更丰富
  • ✅ 只需要基础 CRUD
  • ✅ 周边工具（可视化、备份）更丰富
  • ✅ LAMP/LEMP 技术栈

🔧 GORM 与 PostgreSQL 的关系

⚡ 回答你的问题：GORM 会自动创建数据库/表吗？

GORM AutoMigrate 只会管理表结构，不会创建数据库本身！

GORM 能做什么 vs 不能做什么

操作 GORM 会做 GORM 不会做
数据库不存在 ❌ ❌ 不会创建数据库
表不存在 ✅ 创建表 -
字段不存在 ✅ 添加字段 -
字段类型变化 ❌ ⚠️ 不会自动修改
索引 ✅ 创建/更新 -
约束 ✅ 添加约束 -
外键 ✅ 管理外键 -

实际执行流程

1. 你手动创建数据库
   CREATE DATABASE gin_api;

2. GORM AutoMigrate() 执行时：
   ├── 表不存在？→ 创建表
   ├── 表存在？
   │   ├── 字段不存在？→ 添加字段
   │   ├── 索引不匹配？→ 更新索引
   │   └── 其他变化？→ 忽略（不会删除数据）
   └── 完成

📝 项目中的 GORM 配置

// config/config.go
dsn := fmt.Sprintf("host=%s user=%s password=%s dbname=%s port=%s sslmode=disable",
    cfg.Host, cfg.User, cfg.Password, cfg.DBName, cfg.Port)
DB, err = gorm.Open(postgres.Open(dsn), &gorm.Config{})

// models/user.go
func AutoMigrate() {
    err := config.DB.AutoMigrate(&User{})
}

// main.go
config.InitDB()      // 连接数据库（需要数据库已存在）
models.AutoMigrate()  // 创建/更新表结构

推荐的数据库初始化流程

1. PostgreSQL 安装完成
   ↓
2. 用 pgAdmin / psql 创建数据库
   CREATE DATABASE gin_api;
   ↓
3. 用 pgAdmin / psql 创建表（或让 GORM 创建）
   CREATE TABLE users (...);
   ↓
4. Go 程序连接数据库
   ↓
5. GORM AutoMigrate() 运行（确保表结构最新）

✅ 最佳实践

  1. 手动创建数据库：确保数据库存在
  2. 手动创建表：完全控制表结构（推荐）
  3. 关闭 AutoMigrate：生产环境避免意外变更
  4. 版本管理：使用 migration 文件管理表变更
